# basket-analyst

女子バスケットボール部のアナリスト用 iPad Webアプリ（試合中のスタッツ記録、シュートチャート、クォーター終了時のAI特筆データ）。

- 仕様：[SPEC.md](SPEC.md)
- 開発ルール（Claude Code用）：[CLAUDE.md](CLAUDE.md)

## iPadでの試し方

### 1. GitHub Pages を有効にする（最初の1回だけ）

1. 作業ブランチを `main` に取り込む
2. GitHub のリポジトリ画面で **Settings → Pages** を開く
3. **Build and deployment** の Source を「Deploy from a branch」、Branch を `main`・`/ (root)` にして **Save**
4. 数分待つと `https://goldfish0824-web.github.io/basket-analyst/` で開けるようになる

ビルドは不要です（ファイルをそのまま公開します）。

### 2. iPad のホーム画面に追加する

1. iPad の **Safari** で上の URL を開く
2. 共有ボタン（四角から上向きの矢印）→「**ホーム画面に追加**」
3. 以後はホーム画面のアイコンから開く

ホーム画面に追加しないと、Safari がしばらく使わないサイトのデータを消すことがあります。追加すると電波がなくても開けます（一度ネットにつないだ状態で開いておくこと）。

### 3. まず動きを確かめる（デモ試合）

1. 「設定」→「**デモ試合を作る**」（架空の名前で約120件の記録が入った試合）
2. 集計画面が開く。「ボックススコア」「シュートチャート」「チーム指標・守備隊形別」のタブを確認
3. シュートチャートは チーム／選手／クォーター（前半・後半も可）／守備隊形／種類タグ で絞り込める。印をタップすると内容が出る

### 4. 記録を試す

1. ホーム →「＋ 新しい試合」→ 相手校名・名簿・相手の背番号を入れて「保存して記録へ」
2. 上部の「自DF」「相手DF」で守備隊形を選び、「1Q 開始」
3. 記録のしかた（どのプレーも「選手 → ボタン」「ボタン → 選手」どちらの順でもよい）

| プレー | 操作 |
|---|---|
| シュート | コートをタップ → 選手 → 成功／失敗（境界付近は「2P⇄3P」で切り替え）→ 種類（任意） |
| フリースロー | 選手 → FT成功／FT失敗 |
| リバウンド | OR／DR → 選手（自チームは「チーム」、相手は「番号なし」も可） |
| ターンオーバー | 選手 → ターンオーバー → 種類（任意） |
| アシスト・スティール・ブロック | 選手 → ボタン（自チームのみ） |
| ファウル | 選手 → ファウル（相手は背番号。分からなければ「番号なし」） |
| タイムアウト | タイムアウト → 自チーム／相手 |
| 得点補正 | 得点補正 → 自チーム／相手の +1／+2／+3 |

- 相手の背番号が増えたら「＋番号」で追加（そのまま選んだことになる）
- 間違えたら「取り消し」（直前の1件を消す）か、下のログをタップして修正・削除
- 守備隊形が変わったときだけ「自DF」「相手DF」をタップ。以後の記録に自動で付く
- 「クォーター終了」→ 次の「2Q 開始」。クォーター間もログからの修正はできる

### 5. バックアップ

「設定」→「バックアップを書き出す」→ 共有シートで「ファイルに保存」（または AirDrop）。試合ごとの書き出しはホームの「…」か集計画面の「書き出す」から。読み込みは「設定」→「バックアップを読み込む」。

### 6. 更新されたとき

新しい版を公開したあと、アプリを一度閉じて開き直すと新しい版になります（記録は消えません）。

### パソコンで試す（開発用）

```bash
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開く。テストは次のコマンド（Node 20 以上）。

```bash
node --test
```

## 実装メモ

仕様にない判断をしたところ（1項目1行）。

- 守備隊形：攻撃側のプレー（FG・FT・OR・ターンオーバー・アシスト）には守っている相手の隊形、守備側のプレー（DR・スティール・ブロック・ファウル）にはそのチーム自身の隊形を付ける（ファウルは守備時のものとして扱う）。
- 守備隊形の選択肢は自DF・相手DF共通の1つのリスト。新しい試合の初期値はリストの一番上（マンツー）。
- いまの守備隊形は試合データの `live: { usDF, oppDF }` に保存する（切り替え自体はイベントにしない）。
- イベントの `points` は試投の価値（2P=2、3P=3、FT=1、得点補正=+n）。得点は `made` のときだけ数える。
- 得点補正には守備隊形を付けず、守備隊形別の得点にも入れない（チームの得点とクォーター別得点には入る）。
- 「2P⇄3P」で切り替えたときはゾーンも寄せる（3Pにしたら y≦2.99 はコーナー、それ以外は角度でトップ／45度。2Pにしたら x でミドル左／中央／右）。
- 延長のチームファウルは4Qから続けて数える（FIBA規則）。延長は「延長1」「延長2」と表示し、`quarter` は 5, 6…。
- どのプレーも「選手 → ボタン」「ボタン → 選手」の両方の順で記録できるようにした（リバウンドとほかのプレーで順番が違っても迷わないように）。
- 自チームの「チーム」（選手なし）は OR・DR・ターンオーバーだけ記録できる。相手は全プレーで「番号なし」を選べる。
- 試合前とクォーター間は、コートと右側のボタンを止めて「○Q 開始」を出す（クォーターの取り違え防止）。取り消しとログからの修正は止めない。
- 「クォーター終了」は誤タップ防止のため確認を出す。クォーター終了画面（セッションB）ができるまでは q_end を記録して次のクォーター待ちにするだけ。
- 5ファウルの選手ボタンは押せない。ログからの修正では選べる。
- ログからの修正でできるのは 選手・成功／失敗・2P/3P・種類タグ・守備隊形・削除。シュート位置の修正は削除して入れ直す。
- 記録した直後の内容は右側の案内欄に「記録：自#7 3P成功 右45度」と出す（画面の他の部分を隠さないように）。
- 全データの書き出しには設定（名簿テンプレート・守備隊形の選択肢）も含め、読み込むと置き換える。試合ごとの書き出しには含めない。同じIDの試合は上書きする。
- iPad では書き出しに共有シート（「ファイルに保存」・AirDrop）を使い、それ以外の端末ではダウンロードにする。
- セカンドチャンス得点・速攻得点は、その種類タグが付いたFG成功の得点の合計（FTは含めない）。
- 集計画面はタブ（ボックススコア／シュートチャート／チーム指標・守備隊形別）に分け、スコアとクォーター別得点は常に上に出す。シュートチャートのクォーター絞り込みに「前半」「後半」も入れた。
- 相手チームの表は、記録のある背番号だけを出す。
- 背番号は 0〜99 の数字（"0" と "00" は別の番号）。
- 試合データに `isDemo`（デモ試合の印）、`createdAt`、`updatedAt` を足した。
- `node --test` で ES modules を読むため、`package.json` に `"type": "module"` だけ置いた（ビルドはしない）。
- Service Worker はアプリ本体をインストール時にまとめてキャッシュする。ファイルを足したり変えたりしたら `sw.js` の `CACHE_VERSION` を上げる（`tests/sw.test.js` が一覧の漏れを確認する）。
- 画面は明るい配色のみ（ダークモードなし）。
