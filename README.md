# basket-analyst

女子バスケットボール部のアナリスト用 iPad Webアプリ（試合中のスタッツ記録、シュートチャート、クォーター終了時のAI特筆データ）。

- 仕様：[SPEC.md](SPEC.md)
- 開発ルール（Claude Code用）：[CLAUDE.md](CLAUDE.md)

## iPadでの試し方

### 1. GitHub Pages を有効にする（最初の1回だけ）

1. 作業ブランチを `main` に取り込む
2. GitHub のリポジトリ画面で **Settings → Pages** を開く
3. **Build and deployment** の Source を「Deploy from a branch」、Branch を `main`・`/ (root)` にして **Save**
4. 数分待つと `https://goldfish0824-web.github.io/basket-analyst/` で開けるようになる

ビルドは不要です（ファイルをそのまま公開します）。

### 2. iPad のホーム画面に追加する

1. iPad の **Safari** で上の URL を開く
2. 共有ボタン（四角から上向きの矢印）→「**ホーム画面に追加**」
3. 以後はホーム画面のアイコンから開く

ホーム画面に追加しないと、Safari がしばらく使わないサイトのデータを消すことがあります。追加すると電波がなくても開けます（一度ネットにつないだ状態で開いておくこと）。

### 3. まず動きを確かめる（デモ試合）

1. 「設定」→「**デモ試合を作る**」（架空の名前で約120件の記録が入った試合）
2. 集計画面が開く。「ボックススコア」「シュートチャート」「チーム指標・守備隊形別」のタブを確認
3. シュートチャートは チーム／選手／クォーター（前半・後半も可）／守備隊形／種類タグ で絞り込める。印をタップすると内容が出る

### 4. 記録を試す

1. ホーム →「＋ 新しい試合」→ 相手校名・名簿・相手の背番号を入れて「保存して記録へ」
2. 上部の「自DF」「相手DF」で守備隊形を選び、「1Q 開始」
3. 記録のしかた（どのプレーも「選手 → ボタン」「ボタン → 選手」どちらの順でもよい）

| プレー | 操作 |
|---|---|
| シュート | コートをタップ → 選手 → 成功／失敗（境界付近は「2P⇄3P」で切り替え）→ 種類（任意） |
| フリースロー | 選手 → FT成功／FT失敗 |
| リバウンド | OR／DR → 選手（自チームは「チーム」、相手は「番号なし」も可） |
| ターンオーバー | 選手 → ターンオーバー → 種類（任意） |
| アシスト・スティール・ブロック | 選手 → ボタン（自チームのみ） |
| ファウル | 選手 → ファウル（相手は背番号。分からなければ「番号なし」） |
| タイムアウト | タイムアウト → 自チーム／相手 |
| 得点補正 | 得点補正 → 自チーム／相手の +1／+2／+3 |

- 相手の背番号が増えたら「＋番号」で追加（そのまま選んだことになる）
- 間違えたら「取り消し」（直前の1件を消す）か、下のログをタップして修正・削除
- 守備隊形が変わったときだけ「自DF」「相手DF」をタップ。以後の記録に自動で付く
- 「クォーター終了」→ 次の「2Q 開始」。クォーター間もログからの修正はできる

### 5. バックアップ

「設定」→「バックアップを書き出す」→ 共有シートで「ファイルに保存」（または AirDrop）。試合ごとの書き出しはホームの「…」か集計画面の「書き出す」から。読み込みは「設定」→「バックアップを読み込む」。

### 6. AI特筆データ（クォーター終了時・ハーフタイム）

1. 記録画面で「クォーター終了」→ 確認 → **クォーター終了画面**が開く（そのクォーターと累計のスコア、チームファウル、ファウルトラブルの選手）
2. 「**AI特筆データ**」→ コーチに伝える数字を最大3行で表示。各行の下に根拠の数字（成功-試投と範囲）
3. 「**大きく表示**」で黒背景・特大文字の全画面（タップで閉じる）
4. 「記録へ」→「2Q 開始」で次のクォーターへ。クォーター間は「○Qのまとめ・AI特筆データ」でこの画面に戻れる
5. タイムアウトを記録したときは、右側の案内欄の「ここまでのまとめ・AI特筆データ」から、そのクォーターの途中までの数字で同じ画面を開ける

数字はすべて iPad の中で計算します。AI には背番号と数字の「候補」だけを送り、AI はその中から選んで1行に整えます（選手の名前は送りません）。**AI未設定・通信できない・10秒で応答がない**ときは、iPad の中の順位付けで上位3つを表示し「（自動抽出・AIなし）」と書きます。デモ試合でも、AIなしのまま試せます。

AI を使うには、中継 Worker に追加してから（下の「Workerの追加手順」）、「設定」→「AI接続」に Worker の URL とスタッフ用パスコードを入れて「接続テスト」を押します。

**対処の例（AIに聞く）**：特筆データの各行の「対処の例を聞く」か、画面下の「対処の例（AIに聞く）」の欄に質問を入れて「AIに聞く」を押すと、コーチが選ぶための対処の例を2〜3個表示します（最大20秒）。関連する場面別Q&A へのボタンも出ます（特筆データから聞いたときは、AIなし・電波なしでも出ます）。聞いた内容は試合データに保存し、同じクォーターの画面を開くと見返せます。決めるのはコーチです。

### 7. 振り返り（試合の後）

ホームの試合一覧の「振り返り」（または集計画面・記録画面のメニュー）から開きます。

1. **動画**：YouTube の URL と、動画の何分何秒が試合開始（クォーターごとの動画ならそのクォーター開始）かを入れて「動画を保存」。試合全体で1本でも、クォーターごとでもよい（試合設定でも入れられます）
2. **プレー一覧**：チーム／選手／種類（ターンオーバーだけ、シュートだけ など）／クォーター／守備隊形で絞り込み、各行の「▶ 12:34」で YouTube のその場面を開く。記録はプレーの後に入力するので、設定の巻き戻し秒数（既定8秒）だけ前から再生します。試合の最初から最後まで（ハーフタイムも含めて）続けて録画した動画なら、試合全体で1本・1Q開始の位置だけ入れれば足ります。あるクォーターだけずれるときは、同じ URL を対象「3Q」などで追加し、そのクォーター開始の位置を入れると、そのクォーターだけ合わせ直せます
3. **チェックポイント**：「設定」→「チェック項目」で項目を作り、振り返りで使う項目の「**対象**」にチェックを入れます。項目が多いとき（50程度）は「まとめて追加」に一覧を貼り付け、「すべて対象から外す」→ 使う項目だけチェック、が早いです（「対象だけ表示」で確認）。試合ごとに ◯／△／× とメモで評価。「ターンオーバー12以下」のように目標を入れた項目は、試合の数字から自動で ◯／× が出ます
4. **AI特筆データ**：クォーター終了画面で作った結果をクォーターごとに見返せます（「大きく表示」もここから）
5. **ボックススコア・シュートチャート・チーム指標・守備隊形別**：集計画面と同じ表示

デモ試合でも試せます（動画はどの YouTube の URL でも、開く位置の確認ができます）。

### 8. 画面の配色

標準はダーク（試合中継のスコアボード風）です。明るい体育館で見にくいときは「設定」→「画面の配色」でライトに切り替えられます（その iPad だけの設定）。

### 9. 場面別Q&A（よくある場面と対処の例）

ホームの「場面別Q&A」（記録画面ではメニュー）から開きます。プレス・ゾーン・マンツーマン・守り・リバウンド・速攻・スローイン・終盤のセット・試合運びの42場面について、状況と対処の例、必要に応じてコートの図（● 攻め、▲ 守り、矢印は移動・パス・ドリブル・スクリーン、黄色の札は動きの順番）を見られます。

オールコートのゾーンプレス（2-2-1・1-2-1-1・1-2-2）と、ハーフコートのゾーン（2-3・3-2・1-3-1）は、攻め方をパターンに分けています。図の上の「パターン1」「パターン2」…を押すと、図と動きの説明が切り替わります。マンツーマンのプレッシャー、エースへの厳しいマーク、数的優位の攻め方、終盤のセットも、同じようにパターンで切り替えます。

「フロントコートのセット（終盤）」には、試合終盤にタイムアウトをとり、フロントコートのスローインラインから攻めるときのセットを、【2点】【3点】それぞれ2パターンずつ入れています（手順ごとの図つき）。スローインラインの左右は後半に攻めるゴールで決まるので、図の右上の「左右を反対にする」で、図と説明文（「左ウイング」「右手のドリブル」など）をまとめて左右反対にできます。

- キーワード（ひらがなでも可）とカテゴリで絞り込めます
- 「★ お気に入り」に登録すると、試合中にすぐ開けます
- 「チームのメモ」に、コーチと決めたことを書いておけます（全データのバックアップにも入ります）

内容は一般的な考え方の下書きです。チームとしての方針はコーチと相談して決めてください。電波がなくても見られます。

### 10. 更新されたとき

新しい版を公開したあと、アプリを一度閉じて開き直すと新しい版になります（記録は消えません）。

## Workerの追加手順

AI特筆データの中継は、既存の Cloudflare Worker にハンドラーを1つ足して使います。手順・シークレット（`STAFF_PASS`、`ANTHROPIC_API_KEY`）・変数（`MODEL` など）は [worker/README.md](worker/README.md) にまとめました。デプロイは利用者が行います。

Claude の APIキーの作り方（クレジットと月の上限、**ワークスペースを必ず1つ選ぶこと**、有効期限）、AI が動いているかの確かめ方、うまく動かないときの確認表も [worker/README.md](worker/README.md) にあります。

```bash
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開く。テストは次のコマンド（Node 20 以上）。

```bash
node --test
```

## 実装メモ

仕様にない判断をしたところ（1項目1行）。

- 守備隊形：攻撃側のプレー（FG・FT・OR・ターンオーバー・アシスト）には守っている相手の隊形、守備側のプレー（DR・スティール・ブロック・ファウル）にはそのチーム自身の隊形を付ける（ファウルは守備時のものとして扱う）。
- 守備隊形の選択肢は自DF・相手DF共通の1つのリスト。新しい試合の初期値はリストの一番上（マンツー）。
- いまの守備隊形は試合データの `live: { usDF, oppDF }` に保存する（切り替え自体はイベントにしない）。
- イベントの `points` は試投の価値（2P=2、3P=3、FT=1、得点補正=+n）。得点は `made` のときだけ数える。
- 得点補正には守備隊形を付けず、守備隊形別の得点にも入れない（チームの得点とクォーター別得点には入る）。
- 「2P⇄3P」で切り替えたときはゾーンも寄せる（3Pにしたら y≦2.99 はコーナー、それ以外は角度でトップ／45度。2Pにしたら x でミドル左／中央／右）。
- 延長のチームファウルは4Qから続けて数える（FIBA規則）。延長は「延長1」「延長2」と表示し、`quarter` は 5, 6…。
- どのプレーも「選手 → ボタン」「ボタン → 選手」の両方の順で記録できるようにした（リバウンドとほかのプレーで順番が違っても迷わないように）。
- 自チームの「チーム」（選手なし）は OR・DR・ターンオーバーだけ記録できる。相手は全プレーで「番号なし」を選べる。
- 試合前とクォーター間は、コートと右側のボタンを止めて「○Q 開始」を出す（クォーターの取り違え防止）。取り消しとログからの修正は止めない。
- 「クォーター終了」は誤タップ防止のため確認を出す。クォーター終了画面（セッションB）ができるまでは q_end を記録して次のクォーター待ちにするだけ。
- 5ファウルの選手ボタンは押せない。ログからの修正では選べる。
- ログからの修正でできるのは 選手・成功／失敗・2P/3P・種類タグ・守備隊形・削除。シュート位置の修正は削除して入れ直す。
- 記録した直後の内容は右側の案内欄に「記録：自#7 3P成功 右45度」と出す（画面の他の部分を隠さないように）。
- 全データの書き出しには設定（名簿テンプレート・守備隊形の選択肢）も含め、読み込むと置き換える。試合ごとの書き出しには含めない。同じIDの試合は上書きする。
- iPad では書き出しに共有シート（「ファイルに保存」・AirDrop）を使い、それ以外の端末ではダウンロードにする。
- セカンドチャンス得点・速攻得点は、その種類タグが付いたFG成功の得点の合計（FTは含めない）。
- 集計画面はタブ（ボックススコア／シュートチャート／チーム指標・守備隊形別）に分け、スコアとクォーター別得点は常に上に出す。シュートチャートのクォーター絞り込みに「前半」「後半」も入れた。
- 相手チームの表は、記録のある背番号だけを出す。
- 背番号は 0〜99 の数字（"0" と "00" は別の番号）。
- 試合データに `isDemo`（デモ試合の印）、`createdAt`、`updatedAt` を足した。
- `node --test` で ES modules を読むため、`package.json` に `"type": "module"` だけ置いた（ビルドはしない）。
- Service Worker はアプリ本体をインストール時にまとめてキャッシュする。ファイルを足したり変えたりしたら `sw.js` の `CACHE_VERSION` を上げる（`tests/sw.test.js` が一覧の漏れを確認する）。
- 画面は明るい配色のみ（ダークモードなし）。

セッションB（AI特筆データ）

- 「クォーター終了」→ 確認 → q_end を記録してクォーター終了画面へ自動で移る。次のクォーター開始（q_start）は記録画面で押す（動画との対応に使う時刻を実際の開始に合わせるため）。
- タイムアウトの「まとめ画面」は、クォーター終了画面をそのクォーターの途中の数字で開く形にした（AI に送る形に `inProgress: true` を足す）。
- 候補の範囲は「そのクォーター」「前半（2Q終了時）／後半（4Q終了時）」「累計」。同じクォーターの組み合わせになる範囲（1Q終了時の累計など）は作らず、数字がまったく同じ候補は狭い範囲だけ残す。
- 相手の得点源の偏りは、試投3以上に加えて成功率5割以上のものだけ（「得点源」なので）。「選手×ゾーン」「選手×種類タグ」「選手×左右＋タグ（右ドライブなど）」で作り、同じシュートの集まりはいちばん具体的な言い方だけ残す。左右は x<6.5 が左、x>8.5 が右、その間は正面。
- 相手の得点リーダーは「相手得点の30%以上」に加えて6点以上。
- ターンオーバーの集中は両チームで作る。本数はそのクォーターの範囲で4以上、偏りは4本以上のうち同じ隊形（または種類）が3本以上かつ6割以上。
- リバウンド差は OR で比べる。フリースローは両チーム。流れ（得点差8以上）はそのクォーターの範囲だけ。
- ファウルトラブルの範囲は「2Q終了時」「1Q途中」のように書く。延長の時点は「4以上」だけを条件にする。
- 端末内の点数は 0〜1：ファウル4以上 0.90〜、相手の得点源の偏り（4本以上・7割以上）0.80〜、自チームの極端な不振（5本以上・2割以下）0.70〜、ターンオーバーの集中 0.60〜、リバウンド差 0.50〜、その他 0.45 以下。同じ段では試投数（差・割合）が大きいほど上。
- 端末内の上位3件は、同じカテゴリ×主語（例：相手#7 の得点源）を2つ選ばない。
- AI特筆データの結果は試合データの `insights` に `{ id, quarter, isHalftime, inProgress, createdAt, source: 'ai'|'local', note, items: [{ candidateId, line, candidate }] }` で保存する。候補の数字ごと保存するので、あとで記録を直しても根拠は当時のまま残る。
- AI接続の URL とスタッフ用パスコードは端末の中だけに保存し、バックアップのファイルには入れない。
- Worker は外部ライブラリなしで、Messages API を `fetch` で直接呼ぶ（CLAUDE.md の原則と、既存の中継 Worker にそのまま貼れるようにするため）。
- Worker の `max_tokens` は既定 1000（SPEC は500程度）。Claude Haiku 5.5 は既定で考える（thinking）ため、その分も `max_tokens` に数えられ、500 だと JSON が途中で切れることがあるため。速さは `effort: low` で抑え、応答は JSON スキーマ（structured outputs）で形を固定した。thinking は切らない（`claude-sonnet-5-5` では切る指定が 400 になるため）。変数 `MAX_TOKENS`・`EFFORT` で変えられる。
- Worker は候補が0件なら AI を呼ばずに空の結果を返す（アプリの「接続テスト」に使う）。許可していない Origin からのリクエストは 403 にする。

セッションC（振り返り）

- 動画の秒数は、試合全体の動画なら 1Q の q_start（試合開始）、クォーターごとの動画ならそのクォーターの q_start を基準にする。両方あるときはクォーターごとの動画を使う。同じクォーターの q_start が複数あれば最後のものを使う。
- 動画は `https://youtu.be/ID?t=秒` の形で開く（watch／live の URL も ID を取り出して同じ形にする）。
- 動画の対象は「試合全体」「1Q〜4Q」「延長1・延長2」から選ぶ。開始の位置は「分:秒」か「時:分:秒」で入れる。
- 動画は試合設定と振り返り画面のどちらでも編集できる（同じデータ）。試合設定の YouTube 欄は1本だけから複数に変えた。
- プレー一覧の絞り込みは チーム／選手／種類／クォーター（前半・後半も）／守備隊形。各行にクォーター開始からの経過時間を出す。
- 振り返り画面はタブ（プレー一覧・動画／チェックポイント／AI特筆データ／ボックススコア／シュートチャート／チーム指標・守備隊形別）にし、集計は集計画面と同じ部品を使う。
- チェック項目のテンプレートは最初は空にした（コーチと相談して決める前提のため）。「例を入れる」で SPEC 6-2 の例5項目を足せる。
- 目標にできる数字は、得点・失点・ターンオーバー・OR・DR・OR率・FG%・3P%・FT%・ファウル・アシスト・スティール・セカンドチャンス得点・速攻得点など24種類。「以下／以上」を選ぶ。
- 目標のある項目は ◯／× を試合の数字から毎回計算する（あとで記録を直すと判定も変わる）。手で ◯△× を付けるのは目標のない項目だけ。どちらもメモを書ける。
- 試合の `checklist` には `{ itemId, label, target, mark, memo }` を、評価したときの項目名・目標を写して保存する（あとでテンプレートを変えても過去の試合の評価は変わらない）。テンプレートにだけある新しい項目は「追加する」で足す。
- 巻き戻し秒数とチェック項目のテンプレートは全データのバックアップに含め、読み込むと置き換える。
- チェック項目は設定で「対象」にチェックを入れたものだけを振り返りに出す（項目が50程度ある前提）。新しく足した項目は対象に入った状態で追加する。`active` を持たない古いテンプレートは対象として扱う。
- 「まとめて追加」で1行1項目を貼り付けられる。行頭の「・」「-」「1.」「①」などは外し、同じ名前の項目は飛ばす。
- 対象を変えても、評価済みの試合は評価したときの項目のまま。対象にした項目でまだその試合にないものは、振り返り画面の「追加する」で足す。

デザイン

- 画面の配色は既定をダーク（中継画面風）にし、設定でライトに切り替えられる（端末ごとの設定。バックアップには含めない）。
- スコアや背番号などの数字は iPad に入っている DIN 書体で表示する（ダウンロード不要で、オフラインでも同じ見た目）。DIN がない端末では近い書体になる。
- アイコンは線で描いた SVG を `js/ui.js` に持つ（外部ライブラリなし）。アプリのアイコンも同じ配色に作り直した。
- アプリの名前は利用者の指定で英語にした：ホームの見出しとタブ名は「BasketBall Analyst」、ホーム画面のアイコン名は長いと途中で切れるため「BB Analyst」（ほかの画面の文言は日本語のまま）。
- チームの色（自＝青、相手＝橙）はダーク・ライトそれぞれで、色覚の違いやコントラストの基準を満たす値を使う。

場面別Q&A

- SPEC 第7章フェーズ5「場面別の指示一覧」を先取りした下書きとして、よくある場面（現在42）を入れた。一般的な考え方の例で、チームの方針はコーチと決めて「チームのメモ」に残す前提。文言で「〜すべき」とは書かない。AI への質問の機能は作っていない。
- ルールに関わる記述は FIBA（日本の高校の試合）に合わせた（スローイン5秒、8秒、ショットクロック24秒・オフェンスリバウンド後14秒、チームファウル5つ目から2本、タイムアウトの数、終盤のスローインラインなど）。
- 図は `js/qa-data.js` のデータから SVG で描く。ハーフコートは記録画面と同じ向き（上がゴール）、オールコートは横向きで左から右へ攻める。
- お気に入りとチームのメモは端末内に保存し、全データのバックアップに含めて、読み込むと置き換える。
- 「フロントコートのセット（終盤）」は、試合終盤・タイムアウト後にフロントコートのスローインラインから攻める想定で、【2点】【3点】の2場面に2パターンずつ。公立高校の女子チームでも取り入れやすいよう、スクリーン1〜2回・パス2本以内で、選択肢の順と時間の目安を書いた。図は手順ごとに分けて並べる（`steps`）。
- 1-2-2プレスは守備隊形の初期の選択肢にないため、記録するときは「設定」の守備隊形の選択肢に追加する（Q&A の「アプリで見る数字」にも書いた）。
- 【2点】のパターン1（ピック＆ロール）は、1が右手でドリブルして中央へ攻める向き（左サイドからのスローイン）で図を描いた。スローインラインの左右は後半に攻めるゴールで決まるため、そのことも書き添えた。
- 内容が重なっていた場面を整理して55→43にした（8秒→プレスでターンオーバー、プレス突破後→数的優位、ボックスワン→エースへの厳しいマーク、ディナイ→プレッシャー、2-3ゾーンの2つ、リバウンドの2組、アウトレット→3線速攻、数的不利→速攻の戻り、チームファウル→ファウルが多い、終盤のセット4つ→2点・3点の2つ）。前の ID のお気に入り・チームのメモ・リンクは、起動時とバックアップの読み込み時にまとめた先へ移す（メモが両方にあれば空行でつなぐ）。
- パターンのある場面は `patterns`（name・points・図）で持ち、詳細画面のタブで図と動きを切り替える。そのときの場面の points は「どのパターンでも」共通のこと。選んだパターンはその場面を開いている間（同じタブの間）だけ覚える。
- 動きの順番は、矢印に `n` を付けて黄色の札で描き、説明の先頭の①〜⑨も同じ札で表示する（選手の番号の青い丸と見分けるため）。
- ゾーンプレスの図の番号は役割：4＝スローイン（パスの上手な選手）、1・2＝受け手、3＝中央付近、5＝前方。
- ハーフコートのゾーン（2-3は5、3-2は4、1-3-1は3パターン）も、攻め方ごとに図を分けてパターンで切り替える。「ゾーンの間（ギャップ）を攻める」は2-3のパターン3にまとめた（ほかのゾーンにも同じ考え方のパターンがある）。
- 「左右を反対にする」は、場面に `mirror: true` があるときだけ出す（今は終盤のセット2つ）。図はハーフコートなら x を 15−x にし、説明文は「左」と「右」を入れ替える（「左右」はそのまま）。状態はその場面を開いている間（同じタブの間）だけ覚える。
- パターンや左右の切り替えは、図1枚（SVG の部品50ほど）を描き直すだけなので、パソコンで CPU を4倍遅くしても切り替えは50ms以内だった。図のデータは約98KBで、ほかのファイルと一緒にオフライン用に保存する。
- 戦術を決める人は、画面・Q&A・AIへの指示のどこでも「コーチ」と書く（利用者の指定。もとは「主顧問」）。
- 「対処の例（AIに聞く）」は SPEC 第7章フェーズ5「AI質問」の先取り。アプリの方針（判断はコーチ）に合わせ、AI には「〜すべき」と書かせず「選択肢の例」として出し、画面にも「決めるのはコーチ」と書く。特筆データ（事実）とは別の欄に出す。
- 「対処の例」は Worker の同じ入口（`/basket/insight`）に `kind: "advice"` で送る。既存の Worker の入口のコードを変えずに済むため。Cloudflare の画面で作った Worker 用に、まるごと貼れる `worker/dashboard.js` を用意した（`insight.js` と食い違わないことをテストで確かめる）。
- 個人ファウル5つの候補は「5ファウルで退場」と書く（AI が「ベンチ待機の可能性」と推測で書いたため）。AI への指示にも「推測を書かない」「5つで退場（FIBA）」を足した。
